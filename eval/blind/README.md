# Blind evaluation protocol

**Status: round 1 published — agreement 0.8507, Wilson 95% [0.7466, 0.9169]**
over 67 segments from 50 cases. The filled sheet is
`rounds/round1/answers.csv`; `rounds/round1/result.json` is regenerated by
`scripts/publish_round.py` and the project self-check re-runs it.

What the round established: every disagreement is the Wilson gate, and none of
them is a case of releasing traffic the annotator would fence. Full table,
reproduction command and limits: `rounds/round1/README.md`.

## Why this exists

`dev.jsonl` and `holdout.jsonl` were written by the author of the rules, with
one golden branch per gate. A perfect score against them proves only that the
engine follows its own rules. An independent annotator is the only way to
falsify the claim that those rules match a reasonable release judgement.

## What the annotator sees

`prompts.jsonl`, generated by `scripts/gen_blind_prompts.py`. Each row contains
only `id`, `suite` and `contract`. The fields `expected`, `why` and `kind` are
**deliberately removed** — `kind` would leak which gate is being exercised.
Do not hand-edit `prompts.jsonl`; regenerate it from the suites.

The annotator must NOT see:

- the engine's output for these cases,
- the scored sets or their golden labels,
- this repository's README claims about accuracy.

## The question to answer

For each segment in each contract, answer one question:

> Given this offline evidence and this contract, would you let the model act
> alone on this traffic? Answer `AUTO` (yes), `FENCE` (no, route to a human or
> disable), or `HOLD` (the evidence is not enough to decide).

Record why in your own words. Disagreements are the valuable output: a case
where a careful reader says `FENCE` and the engine says `AUTO` is a candidate
defect, not an annotation error to be smoothed away.

## Annotation file format

Put independent annotations at `eval/blind/annotations.jsonl`, one JSON object
per line:

```
{"id":"dev-001","verdicts":{"thin":"HOLD"}}
{"id":"ho-007","verdicts":{"five_hundred":"FENCE","one_thousand":"AUTO"}}
```

This file is gitignored on purpose: it is a measurement input, not a source
file, and it must not be silently committed as if it were a result.

## Scoring

```
python scripts/blind_eval.py
python scripts/blind_eval.py eval/blind/annotations.jsonl
python scripts/blind_eval.py eval/blind/annotations.jsonl --json
```

The script compares the annotator **against the engine's verdicts**, not
against the author-written golden labels. It reports agreement, a Wilson 95%
interval when the sample permits, and a full disagreement list. With no
annotation file it prints `NOT RUN` and invents no number.

Agreement here is not a model accuracy figure. It is a measure of how often an
independent reader agrees with deterministic gates, and its interval will be
wide until enough cases are annotated.

## Human-readable annotation packet

**One-file handout:** `盲评填写表.csv`, generated by
`python scripts/gen_single_sheet.py`. It contains every input field plus empty
`你的判定` and `理由` columns, with Chinese headers and a BOM for Excel / WPS.
Score a filled copy directly with
`python scripts/blind_eval.py <path-to-filled.csv>`.

Run `python scripts/gen_blind_packet.py` to regenerate the detailed packet
from the prompts:

- `ANNOTATOR_GUIDE.md` — self-contained instructions; contains no results,
  no answers and no accuracy figures.
- `worksheet.md` — one table per case with empty verdict and reason columns.
- `answer_sheet.template.csv` — one row per segment, empty verdict column.

Copy the template to `answer_sheet.csv` (gitignored), fill it in, then score it
with `python scripts/blind_eval.py eval/blind/answer_sheet.csv`. The script
accepts CSV or JSONL, skips undecided rows and reports how many segments remain
unannotated. Undecided rows are never guessed and never counted as agreement.

Project self-checks assert that the packet stays in sync with the prompts,
that every verdict cell stays empty in the shipped template, and that no
accuracy figure leaks into any file an annotator sees.

The scoring script labels each disagreement with its cause
(`wilson_lower_below_floor_but_point_estimate_above` versus
`other_gate_or_judgement`), so a second round can be grouped the same way
without hand analysis.

This is a **known conservative bias, not a defect to be patched away**: the
whole point of gate G2 is to refuse point-estimate reasoning. A team that
deliberately wants point-estimate semantics should not use this tool.

## Publishing a round

A round is publishable only if its sheet ships with it — a rate whose input
nobody can re-run is the unfalsifiable claim this project rejects. Use:

```
python scripts/publish_round.py --round N \
  --sheet eval/blind/rounds/roundN/answers.csv \
  --out   eval/blind/rounds/roundN/result.json \
  --date YYYY-MM-DD --annotator "<who and what they did not see>"
```

The script refuses to overwrite a different published result without `--force`,
and the self-check recomputes every published round from its sheet.

⚠️ **Round 2 must use fresh annotators who have not read `rounds/round1/`.**
Once answers are public, anyone who has seen them cannot produce a blind
measurement. A ready-to-hand-out sheet and the admission rules are in
`next_round/`; the project self-check keeps that sheet blank and in sync.
